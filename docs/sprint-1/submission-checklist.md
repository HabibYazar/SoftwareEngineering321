# Sprint 1 — Submission checklist

- [ ] Proposal names stakeholders, hypotheses, feasibility, risks and open-source license.
- [ ] Vision, boundary, release scope, API and backlog agree on the same first release.
- [ ] API YAML parses, operations have schemas and representative normal/error outcomes.
- [ ] Six students have instructor-approved named roles; RACI one A per activity.
- [ ] GitHub `main` and `develop` protections actually enabled in UI.
- [ ] Issue IDs link to PRs, reviews, CI, diagrams and deliverables.
- [ ] Team/repository URL, release tag `sprint-1`, owners, evidence links supplied.
- [ ] University and contributor rights checked before publishing under Apache-2.0.
- [ ] Peer-review exercise: another team can explain scope and mock a client from OpenAPI.

**Sprint 1 is a foundation deliverable, not a claim that the full HMS is built.**
