# Contributing

1. Confirm eligibility to contribute and agreement on licensing with the course team.
2. Create or link an issue with testable acceptance criteria.
3. Branch off `develop` with `feature/<issue>-<summary>` (or `fix/<issue>-<summary>`).
4. Update the appropriate module, tests, API draft, and docs together.
5. Open a PR into `develop`, link the issue, and provide test evidence.
6. Request review from **at least one other member**, preferably module owner; no self-merge without review.
7. Merge only after required CI checks pass. Tag the sprint submission from `main`.

**Never commit real patient information, credentials or access tokens.** Never copy proprietary Enterprise sources into this public repo.
